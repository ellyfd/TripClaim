# 報支整包規則

出差回來「結帳」時，把單據整理成可直接送件的一包。這份規則來自一次實際報支的來回修正。引導流程見 [SKILL.md](../SKILL.md)，版面由 `scripts/build_pack.py` 實作。

## 1. 金額與幣別

幣別在系統選單裡的外幣，**報原幣或換台幣由本人決定**，不預設一定要換台幣。手續費很小、截圖麻煩，直接報原幣是常見選擇。

| 情況 | 怎麼報 |
|------|--------|
| 報原幣（不用信用卡明細） | 報原幣（例如歐元），不自行換算。系統帶的匯率會顯示成「公司匯率×1.025」（例：36.194X1.025），不用自己算 |
| 本人選擇換台幣（要有信用卡明細） | 報台幣，金額 = 台幣入帳 + 該筆的國外交易手續費 |
| 幣別**不在**系統選單裡（例如波蘭幣 PLN） | 只能轉台幣報。**沒有固定匯率、不要自己換算**：台幣金額就是刷卡明細上的入帳 + 手續費。所以這種消費一定要有刷卡明細 |

- 手續費跟著它所屬的那一筆，不另外開「國外交易手續費」一列。
- 系統選單的幣別清單見 [system-fields.md](system-fields.md)。

### 一列怎麼分

報支表的一列 = **一個項目 × 一個幣別**。同項目、同幣別的全部加總成一列，不管來自幾個城市、幾張訂單。

- 同項目、不同幣別，分列。例：餐飲 歐元 一列、餐飲 台幣 一列。
- 換成台幣的（信用卡明細換的、幣別不在選單被迫轉的）都併進該項目的台幣列。例：訂房網站房費 13,319 + 飯店現場 EUR 58.40 換成的 2,149 + 手續費 32 = 一列住宿 15,500；波蘭住宿轉台幣也併進同一列住宿 台幣。
- 被迫轉台幣的那部分，在 Remark 註明「沒有波蘭幣，轉台幣，PLN 391.52（3,344＋手續費 50）」：原幣金額照收據，括號裡的台幣和手續費照刷卡明細抄，不經任何匯率計算。
- 預支歸還固定一列：幣別＝預支的幣別，金額＝要歸還的現金（沒有就 0），憑證 0。
- 列的順序不用照下拉選單排。
- 帳單對不上收據（金額或商家不同）時，視為另一筆消費，不可硬配。

## 2. 報支表（Excel）

只留公司系統「旅費報支申請」的七欄，順序相同，不加其他欄位：

`項目｜幣別｜金額｜憑證數｜附件｜Remark｜費用歸屬`

- 項目用系統下拉選單的名稱（完整清單見 [system-fields.md](system-fields.md)）。
- Remark 寫金額組成（原幣金額、台幣入帳、手續費）。有被迫轉台幣的消費，註明「沒有○○幣，轉台幣，原幣金額（台幣＋手續費）」。
- 住宿、餐飲、車資的 Remark 寫人數（例：「1人入住」、「收據上有註明 2 人，為包含 2 人費用」、「旅館到客戶來回車資 for 3人」）。一張單據涵蓋多人時，在收據上也寫明人數。
- 費用歸屬留空、不用問，本人在系統裡自己選。

### 憑證數算法

| 憑證 | 張數 |
|------|------|
| 原幣收據／發票 | 1 |
| 台幣入帳明細 | 1 |
| 手續費明細 | 1（即使和入帳在同一張截圖裡，也分開各算一張） |
| 登機證 | 每張 1（來回 = 2） |

## 3. 整包（zip）結構

```
要印.pdf              ← 外層，一份合併檔，直接印
<出差名稱>.xlsx       ← 外層
上傳/                 ← 一個報支項目一個檔，照系統項目命名
  1_機票(自行刷卡).pdf
  2_住宿.pdf
  3_餐飲.pdf
  ...
```

- 「上傳」的每個檔放該項目的全部憑證，含實體收據的照片。
- 同項目有多筆時用編號稱呼：餐1、餐2、餐3；車1、車2。編號要和 Excel 的 Remark 對得上。
- zip 內的中文檔名必須標記為 UTF-8（Python `zipfile` 會自動處理；Info-ZIP 的 `zip` 指令不會，Windows 會看到空的或亂碼）。

## 4. 要印.pdf 的規則

三種來源，三種處理：

| 來源 | 要不要印 | 尺寸 |
|------|----------|------|
| 實體單據（登機證、紙本收據、刷卡單、紙本發票） | 不印照片，交實體 | 只有**小張收據／刷卡單**要在頁面上留位（虛線框，供黏貼）；A4 紙本和登機證不留位 |
| 電子檔（電子收據、電子發票 PDF） | 要印 | **不可縮小**，A4 上 100% |
| 截圖（信用卡明細、手續費） | 要印 | 縮到**手機實際大小**後合併 |

細節：

- 登機證一律交實體，不印。
- 截圖實際大小 = 像素寬 ÷ 手機 ppi（例：1179px ÷ 460ppi ≈ 65mm 寬）。
- 截圖依報支項目合併：車和車一頁、餐和餐一頁，不依卡別分。
- 每個項目的順序：截圖頁（小收據的留位框放在同一頁）→ 該項目的電子收據。
- 留位框大小要一樣，不要大大小小：每個寬 80mm（熱感紙收據寬度）、高約 A4 的一半；小張的貼在框內，太長的收據摺起來貼。
- 整個項目都報原幣、沒有信用卡明細時，不留右邊的截圖區，留位框兩欄兩列排滿一頁（一頁 4 個）。
- 留位框和截圖放同一頁：留位框在左（上下疊），截圖在右、分成上下兩列，每列的頂端對齊左邊對應的留位框（有實體收據的那幾筆在上列，其餘在下列）。右側放不下時留位框尺寸不動，截圖等比例略縮到剛好放得下（仍要看得清楚）。
- 截圖頁不列卡別和卡號末四碼（標題只寫「車資｜信用卡明細」這類）。
- 每一筆截圖下方註明憑證在哪：「見下一頁」、「見下兩頁」，或「左上／左下黏貼處」。
- 同一頁有多筆時，筆與筆之間留一段間距（約 1cm），看得出哪幾張是同一筆。
- 美規 Letter 尺寸的電子收據（例如 Uber）要放到 A4 頁面上維持 100%，否則印表機會自動縮小。
- Uber／Uber Eats 收據只印第一頁（金額頁），不印路線地圖或外送明細那頁。
- 沒有金額依據作用的截圖（例如從別的表格截下來的金額）不放。
- 列印時選「實際大小」，不選「符合頁面」。

## 5. 過程中的原則

- 看不出用途、對不上帳的單據，先問本人，不猜。
- 收據品名和本人說的不一致時，照本人說的歸類，但把收據原品名留在 Remark。
- 每次改版另存新版號，不覆蓋前一版。
