# 報支整包規則

出差回來「結帳」時，把單據整理成可直接送件的一包。這份規則來自一次實際報支的來回修正，之後的整包（不論人工、Claude 或 app 功能）都照這份做。

## 1. 金額與幣別

| 情況 | 怎麼報 |
|------|--------|
| 有信用卡明細（看得到台幣入帳金額） | 報台幣，金額 = 台幣入帳 + 該筆的國外交易手續費 |
| 沒有信用卡明細 | 單報原幣（例如歐元），不自行換算 |

- 手續費跟著它所屬的那一筆，不另外開「國外交易手續費」一列。
- 同一個報支項目、都已換成台幣的，加總成一列（例如訂房網站房費 + 飯店現場加收 + 手續費 = 一列住宿）。
- 帳單對不上收據（金額或商家不同）時，視為另一筆消費，不可硬配。

## 2. 報支表（Excel）

只留公司系統「旅費報支申請」的七欄，順序相同，不加其他欄位：

`項目｜幣別｜金額｜憑證數｜附件｜Remark｜費用歸屬`

- 項目用系統下拉選單的名稱（見 `app/managed-config.ts` 的 `DEFAULT_CLAIM_TYPES`）。
- Remark 寫金額組成（原幣金額、台幣入帳、手續費）。
- 費用歸屬不代填，留給本人。

### 憑證數算法

| 憑證 | 張數 |
|------|------|
| 原幣收據／發票 | 1 |
| 台幣入帳明細 | 1 |
| 手續費明細 | 1（即使和入帳在同一張截圖裡，也分開各算一張） |
| 登機證 | 每張 1（來回 = 2） |

## 3. 整包（zip）結構

```
要印.pdf              ← 外層，一份合併檔，直接印
<出差名稱>.xlsx       ← 外層
上傳/                 ← 一個報支項目一個檔，照系統項目命名
  1_機票(自行刷卡).pdf
  2_住宿.pdf
  3_餐飲.pdf
  ...
```

- 「上傳」的每個檔放該項目的全部憑證，含實體收據的照片。
- 同項目有多筆時用編號稱呼：餐1、餐2、餐3；車1、車2。編號要和 Excel 的 Remark 對得上。
- zip 內的中文檔名必須標記為 UTF-8（Python `zipfile` 會自動處理；Info-ZIP 的 `zip` 指令不會，Windows 會看到空的或亂碼）。

## 4. 要印.pdf 的規則

三種來源，三種處理：

| 來源 | 要不要印 | 尺寸 |
|------|----------|------|
| 實體單據（登機證、紙本收據、刷卡單、紙本發票） | 不印照片，交實體 | 在頁面上**留位**：畫出實際大小的虛線框，供黏貼 |
| 電子檔（電子收據、電子發票 PDF） | 要印 | **不可縮小**，A4 上 100% |
| 截圖（信用卡明細、手續費） | 要印 | 縮到**手機實際大小**後合併 |

細節：

- 登機證一律交實體，不印。
- 截圖實際大小 = 像素寬 ÷ 手機 ppi（例：1179px ÷ 460ppi ≈ 65mm 寬）。
- 截圖依報支項目合併：車和車一頁、餐和餐一頁，不依卡別分。
- 每個項目的順序：截圖頁（含實體收據留位）在前，該項目的電子收據接在後。
- 留位大小照單據實際尺寸：熱感紙收據約 80mm 寬、刷卡單約 57mm 寬、登機證約 200 × 83mm。A4 大小的實體發票不留位，另附於後。
- 美規 Letter 尺寸的電子收據（例如 Uber）要放到 A4 頁面上維持 100%，否則印表機會自動縮小。
- Uber／Uber Eats 收據只印第一頁（金額頁），不印路線地圖或外送明細那頁。
- 沒有金額依據作用的截圖（例如從別的表格截下來的金額）不放。
- 列印時選「實際大小」，不選「符合頁面」。

## 5. 過程中的原則

- 看不出用途、對不上帳的單據，先問本人，不猜。
- 收據品名和本人說的不一致時，照本人說的歸類，但把收據原品名留在 Remark。
- 每次改版另存新版號，不覆蓋前一版。
